# 拆解方法

这一页总结本站拆解战斗系统时用到的方法。每种方法都按同一个顺序写：**用了什么功能的工具 → 得到了什么结果 → 这些结果能回答什么问题**，再链接到用过它的文章段落。这里不提供脚本；工具会随游戏版本失效，方法本身更值得复用。

## 一篇拆解案要回答的问题

本站的拆解案（拆一款作品的某个战斗系统）都尝试回答下面九个问题。它们不一定适合所有人的写法，但大方向对任何一篇战斗拆解都适用。

| # | 问题 | 为什么要回答 |
|---|---|---|
| 0 | **这篇要解决哪个设计问题？** 结论在哪个版本、什么条件下成立？ | 问题不聚焦，后面的数据就没有落点；版本不冻结，数据就无法复核 |
| 1 | **规则怎么运转？** 一次输入怎样一步步变成最终结果？ | 把结算顺序、叠加方式和关键系数拼成一条链，并给出一个能用计算器复算的例子，读者才能检验结论 |
| 2 | **关键数值为什么是这个值？改了会怎样？** | 只描述数值是记录，追问“为什么不是相邻的值”才是设计分析 |
| 3 | **对手一侧怎么设计？** 敌人、BOSS 或对手怎样行动，在考玩家什么？ | 战斗是双方的事，只看玩家一侧只拆了一半 |
| 4 | **规则产生的事件，怎样变成玩家的感受？** | 顿帧、缓冲、取消窗口、镜头、音效、命中反馈决定了规则“摸起来”是什么样 |
| 5 | **战斗和成长、资源、关卡怎么咬合？** | 同一套规则放进不同的成长阶段和关卡节奏，体验可能完全不同 |
| 6 | **成在哪、败在哪？代价是什么？** | 每个设计决策都在换取什么、放弃什么；评价要有证据，不能只靠体感 |
| 7 | **如果改，怎么改？改了是否成立？**（格斗游戏角色篇不设这一问，见下） | 改法要放回同一个模型里验证，否则只是一份想法清单 |
| 8 | **用了什么方法？哪里不确定？** | 读者需要知道每个结论站在哪种证据上 |

**格斗游戏角色篇不设第 7 问。** 没有超大量的实战对局可供分析，就无法验证一处——哪怕再微小——的改动「不会让游戏整体的平衡失衡」。所以这类文章假设**当前版本就是这款游戏发售以来最好的平衡版本**，不做角色修改，只做分析：揣摩开发者在角色身上做的取舍，回答「这个角色为什么是这个样子，而不是另一个样子」。第 2 问的反事实仍然保留，它回答的是「这个数为什么是它、偏一点会怎样」，而不是「应该改成什么」。

品类史（如《回合制的进化史》《射击的进化史》）性质不同，它们沿时间线讲规则怎样演变，作为拆解案的导航页，不按上面的问题逐条展开。

## 证据等级

文章中的关键结论按证据来源区分：

| 等级 | 含义 |
|---|---|
| 文件 | 直接读自游戏数据文件或配置 |
| 代码 | 读自反编译、反汇编或官方公开源码 |
| 实测 | 实机测量，写明样本量与误差 |
| 官方 | 官方补丁说明、手册、开发者表态 |
| 模型 | 由上述证据推出的计算或模拟结果，写明假设 |
| 推断 | 有证据支持但没有直接确认 |
| 社区 | 社区资料与 Wiki，只作旁证或标明来源 |

## 方法目录

### 1. 读游戏数据文件：解包与数据表导出

- **工具功能**：解开游戏资源包（解压、解密、拆容器），把数据表或资产按字段导出成可读的表格。
- **得到的结果**：武器、护甲、敌人、技能、刷新表、难度预设等的原始数值；资产之间的引用关系。
- **能回答的问题**：数值到底是多少；哪些对象共享同一份数据；两个版本之间改了什么。
- **用过的地方**：
  - Valheim：解析资源包里的预制体，读出武器、护甲、敌人、配方、刷新与掉落表（[附录 B](./valheim/full.md#appendix-B)）；
  - 战地风云 6：逐块解压资源，导出约 89.8 万个资产分区，发现 7 把 5.56 突击步枪引用同一份子弹数据（[§2.1](./bf6/full.md#section-2-1)）；
  - ASW：从 Xrd、Strive、BBCF 的资源包中解出角色脚本与碰撞文件（[附录 B](./asw/full.md#appendix-B)）；
  - 回合制：P5R、空之轨迹 the 2nd 的战斗数据表，XCOM 2 的配置文件（[附录 B](./turn-based/full.md#appendix-B)）。
- **局限**：数据表里只有“写进表的东西”。很多关键常量写死在代码里，表里读不到，需要方法 2。

### 2. 定位代码中的规则：反编译、反汇编与读源码

- **工具功能**：把托管程序集反编译成可读代码；对原生可执行文件做静态反汇编和交叉引用；直接阅读官方公开的源码。
- **得到的结果**：结算的执行顺序、公式、分支条件，以及只存在于代码里的常量。
- **能回答的问题**：一次攻击按什么顺序结算；某个倍率是加法还是乘法；为什么数据表里找不到某个数。
- **用过的地方**：
  - Valheim：从反编译代码还原完整的伤害结算管线，发现被格挡的残余伤害累积了两次架势（[§2](./valheim/full.md#section-2)、[附录 A](./valheim/full.md#appendix-A)）；
  - 回合制：P5R 换手倍率和空之轨迹 the 2nd 延迟换算都不在数据表里，在可执行文件中定位到（[附录 B](./turn-based/full.md#appendix-B)）；
  - 射击史：德军总部 3D、毁灭战士、雷神之锤、半条命的公开源码，以及 CS 系列的随机数与后坐力链路（[附录 A](./shooting/full.md#appendix-A)）。
- **局限**：静态分析只能证明“代码这样写”，运行时是否走到这条分支，需要实测或交叉核对。

### 3. 还原时间轴：动画事件与逐帧脚本

- **工具功能**：读取动画控制器的状态、过渡和动画事件，按播放速度换算成真实时间；对格斗游戏的角色脚本逐帧累加，再对照每帧的攻击判定框。
- **得到的结果**：一招的出招、命中、可接下一招的时刻；连段的总时长；命中后还能取消多久；顿帧长度。
- **能回答的问题**：玩家一套连段要多久、什么时候会被打断；敌人出招前有多少预兆；“手感变宽松”到底宽在哪里。
- **用过的地方**：
  - Valheim：单手剑三段攻击的时间轴，与实测相差 0.6%；敌人每种招式独立冷却（[§5.6](./valheim/full.md#section-5-6)）；
  - ASW：三作的帧顿表、按键缓冲与逐招取消窗口，结论是 Strive 放宽的不是帧顿，而是缓冲和取消规则（[§6.2](./asw/full.md#section-6-2)）。
- **局限**：时间轴来自资源文件，引擎在运行时可能另有修正，需要与实测或社区帧数表核对。

### 4. 判定框逐帧解析

- **工具功能**：解析碰撞文件里的判定数据（攻击判定框与受创框），按贴图名把每一帧的框对齐到角色的状态时间轴。
- **得到的结果**：每招持续期内每一帧的判定框坐标（最远 / 最高 / 最低）与受创框范围。
- **能回答的问题**：一招的判定存在几帧、覆盖多远的距离带、在持续期内怎么变；两个角色的同一个招式位在距离上差多少。
- **用过的地方**：BBCF 拉格纳的 `5B` 时间轴与全角色最远判定对比（[§2.1](./bbcf-ragna/full.md#section-2-1)、[§4.2](./bbcf-ragna/full.md#section-4-2)～[§4.4](./bbcf-ragna/full.md#section-4-4)）；ASW 从三作的碰撞文件解出判定数据（[附录 B](./asw/full.md#appendix-B)）。
- **局限**：判定框本身不说明它什么时候生效——框挂在贴图上，还要知道那张贴图排在第几帧；判定在生成物、傀儡或「换一套框」上的招式，必须对齐到载体才不会漏。

### 5. 交叉核对：确认读出来的数是对的

- **工具功能**：把本地读出的数据与另一来源逐项对照；用一个来源的已知值检验另一个来源的解读。
- **得到的结果**：字段含义的确认、匹配率、互相矛盾的地方。
- **能回答的问题**：哈希化的字段名代表什么；我的时间轴算法有没有算错；社区数据能不能用。
- **用过的地方**：
  - 战地风云 6：与带字段名的公开数据逐项对照，61 把武器中 59 把自动匹配（[§1.1](./bf6/full.md#section-1-1)）；
  - ASW：脚本里读出的攻击等级与社区帧数表逐招一致，按脚本算出的发生帧也与帧数表几乎逐招一致（[§6.2](./asw/full.md#section-6-2)）。
- **局限**：两个来源同出一源时，核对不能提高可信度。

### 6. 实机录像测量

- **工具功能**：从音轨检测射击时刻；对画面逐帧做配准，得到镜头旋转；用界面刻度把像素换算成角度；对相邻帧做差分，提取弹着点；用目标检测加人工复核测距离。
- **得到的结果**：每发后坐力的方向与幅度、回正速度、弹匣之间的离散、子弹扩散的实际大小、实战交战距离的分布。
- **能回答的问题**：文件里的参数在游戏里实际怎样起作用，例如“随机范围”指的是全宽还是正负各一份、“扩散值”是半径还是直径。
- **用过的地方**：战地风云 6 的后坐力、扩散、移动惩罚与交战距离（[§1.2](./bf6/full.md#section-1-2)、[§3.3](./bf6/full.md#section-3-3)、[§4.2](./bf6/full.md#section-4-2)、[§6](./bf6/full.md#section-6)）。
- **局限**：单一射手、样本量有限、换算有误差；结论要写成上下界。

### 7. 从实机读数反推公式

- **工具功能**：一次只改变一个变量（例如角色速度），记录游戏界面显示的结果；再固定这个变量、改变另一个（例如动作类型）；用候选公式拟合，并排除其他取整方式。
- **得到的结果**：公式形式、常数、取整方式。
- **能回答的问题**：界面只显示结果、不显示公式时，规则到底是什么。
- **用过的地方**：
  - 回合制：空之轨迹 the 2nd 的行动延迟公式，先由实机读数拟合，再在可执行文件中核对到换算函数（[附录 B](./turn-based/full.md#appendix-B)）；
  - 战地风云 6：从烘焙伤害表的数值规律反推出“一发四肢命中不增加击杀发数”的设计（[§2.3](./bf6/full.md#section-2-3)）；回正速度用递推式拟合（[§3.3](./bf6/full.md#section-3-3)）。
- **局限**：数据点要覆盖变量范围的两端；拟合成功不等于找到了真实公式，最好再用方法 2 确认。

### 8. 模型与模拟

- **工具功能**：把前面得到的规则和数值写成可运行的模型；对含随机项的情况做蒙特卡洛模拟（固定场景、大量重复）；对行为假设做敏感性测试。
- **得到的结果**：死亡率、平均损血、战斗时长、有效射程分布等统计量；改变某个参数前后的对比。
- **能回答的问题**：一组规则组合起来，在实战里意味着什么；结论对假设有多敏感；改一个参数会怎样。
- **用过的地方**：
  - Valheim：步长 0.02 秒的遭遇战模拟，四种打法、两种难度，每个场景数百次；另有召唤法师、远程开局与敏感性测试（[§5.6](./valheim/full.md#section-5-6)、[§5.7](./valheim/full.md#section-5-7)、[§10.7](./valheim/full.md#section-10-7)、[附录 D](./valheim/full.md#appendix-D)）；
  - 战地风云 6：单次扫射的有效射程模拟，每把枪 20,000 次；去掉方向随机后再跑一遍作为对照（[§1.3](./bf6/full.md#section-1-3)、[§5](./bf6/full.md#section-5)）。
- **局限**：模型里的行为假设（玩家怎样操作、敌人从哪里来）不来自文件，必须单独列出，并测试改变它们时结论是否还成立。

### 9. 连段拆分与窗口计算

- **工具功能**：把一套连段拆成一个个衔接，按“取消、目押、空中追打、延迟或位置依赖”分类；用帧数表计算能算的窗口。
- **得到的结果**：每套连段的衔接构成、长度、延迟数、限定条件，以及可计算窗口的上界。
- **能回答的问题**：一套连段难在哪里；“变简单了”具体是哪一类衔接变少了。
- **用过的地方**：ASW 四个角色各代主力连段（[§1.4](./asw/full.md#section-1-4)、[§6.1](./asw/full.md#section-6-1)、[附录 B](./asw/full.md#appendix-B)）。
- **局限**：帧数表只能回答“有没有窗口”；空中追打缺少受身不能时间时只能算上界。

### 10. 全角色同位置横向对比

- **工具功能**：把同一个招式位（例如 5B、2D、66、44、对空无敌技）在各角色上的发生 / 持续 / 收招 / 判定 / 命中与被防有利帧 / 补正并排；先核对各角色的状态是不是同一个东西，再决定样本。
- **得到的结果**：一个数值在全体里是极端值还是惯例；同一个「招式位」实际包含几种不同的设计。
- **能回答的问题**：某个取舍是刻意设计还是数值惯性；「这个角色像某某模板」这类框架能成立几分。
- **用过的地方**：BBCF 拉格纳的 `5B` / `2D` / `6A` / `66` / `44` 与投射物横向表（[§4.2](./bbcf-ragna/full.md#section-4-2)～[§4.6](./bbcf-ragna/full.md#section-4-6)）；同为 rushdown 定位的五名角色的同类并排（[§6.6](./bbcf-ragna/full.md#section-6-6)）；ASW 四个角色各代核心连段的并排（[§6.1](./asw/full.md#section-6-1)）。
- **局限**：横截面只能说明「现在是什么样」，说明不了「为什么变成这样」；样本口径一变（例如「2D」在各角色身上算不算同一个招式位），排名跟着变。

### 11. 社区资料计量

- **工具功能**：对社区资料的文本按关键词规则自动分类计数，再人工抽查估计精确率。
- **得到的结果**：某类现象在不同版本中的比例，例如带角色限定注释的连段条目占比。
- **能回答的问题**：某种设计趋势在跨版本层面是否存在。
- **用过的地方**：ASW 角色限定注释的跨代统计，人工抽查 40 条，精确率约 88%（[§6.3](./asw/full.md#section-6-3)）。
- **局限**：反映的是页面的写法，不是实战中遇到该现象的频率；不同编者、不同年份的写法差别很大。

### 12. 玩家体验统计

- **工具功能**：抓取评测与在线人数的公开数据，按时间分段；对评测文本按主题分类，用显著性检验比较不同时期的占比。
- **得到的结果**：好评率与在线人数的变化，某类抱怨占比的变化及其显著性。
- **能回答的问题**：机制问题是否对玩家体验产生了可测的影响。
- **用过的地方**：战地风云 6 的 Steam 评测与在线人数（[§12](./bf6/full.md#section-12)）。
- **局限**：只能说明相关，不能单独证明因果；版本内容、营销和外部事件都会影响这些数字。

### 13. 史料与设计史

- **工具功能**：检索开发者访谈、GDC 演讲、官方手册与规则书，按来源分级，交叉核对引语。
- **得到的结果**：设计者自述的意图、规则在各代的变化、时间线。
- **能回答的问题**：一条规则为什么在那个时间点出现；设计者想解决什么问题。
- **用过的地方**：两篇品类史的全部史料（[回合制附录 C](./turn-based/full.md#appendix-C)、[射击史附录 B](./shooting/full.md#appendix-B)），以及拆解案中引用的开发者表态。
- **局限**：设计者的回忆可能与当年的实际不符；二手转述要回到原文核对。

### 14. 第三方连段视频样本

- **工具功能**：把「combo collection」类教学视频解析成结构化连段表——按固定版面抽出画面底部的连段记法条与左侧分区标签，用列剖面距离把「同一条记法」的连续帧归成一段，拼成印相表逐条抄写，再把括号里的伤害数字放大 2 倍逐条复核；记法里的招式略称用视频自带的对照表还原。
- **得到的结果**：每名角色一份连段表（分区、伤害、作者原写法、视频时间戳），以及按层（基础连段 / 含进阶 / OD 斩杀）重算的伤害分布与名次。
- **能回答的问题**：在**另一份独立样本**上，一个角色的火力分布是什么形状（均火高还是斩杀高）、连段的进阶部分能带来多少增益、从常规切到 Overdrive 的收益有多大。
- **用过的地方**：BBCF 角色拆解案的回报一章——32 名角色、1,432 条连段的火力分层（[§4.4](./bbcf-ragna/full.md#section-4-4)）。
- **局限**：路线集是各视频作者自己挑的（「中位」是该作者视角下的中位），视频里的伤害是作者标注而不是游戏读数；连段伤害计数器不含「不计入命中的伤害」（设置物的持续伤害、吸血环），所以对这类角色是低估；样本口径与「连段页 Core 连段」不同，两份样本只能互相旁证，不能并排排名。

## 测试设计的几条通用做法

上面的方法在具体操作中反复用到几条原则：

1. **一次只改一个变量。** 反推公式时固定动作改速度，再固定速度改动作；比较版本时只看同一角色、同一招式。
2. **随机项靠重复和分组来控制。** 多录几个弹匣、多跑几百次模拟，看分布而不是单次结果；需要估计误差时按样本分组重抽样。
3. **先测“已知答案”的样本。** 首发扩散、发生帧这类已知值先测一遍，确认测量本身的噪声足够小，再测未知的部分。
4. **把行为假设和文件数据分开。** 模型里凡是不来自文件的部分都单独列出，并改变它们看结论是否还成立。
5. **结论按证据等级标注。** 模拟结果标“模型”，没有直接确认的标“推断”。
