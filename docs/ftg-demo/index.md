# FTG 角色原型：D 系位移与连段选路

**个人项目 · 设计实验 · Godot 可运行原型**

能否用 BB Drive System 式的输入组织，简化 Seth 式连段中反复的位移指令，同时保留位置选择？这个 Demo 把部分位移攻击放进 D 系，实现了双换边搬运、抵墙短线和原版边保位。**位移输入得到集中，墙距仍决定连段如何继续。**

当前八样本路线已完成机器验证；这一版的操作宽容度与真人手感待试玩。公开版本固定为 `6998168`，功能报告日期为 2026-10-12。

## 一个值得继续调的问题

长线的关键 `jC` 连接仍有 1 帧窗口。**部分动作少了复杂指令，整条路线仍要求严格节拍。** 下一轮将围绕实际失败原因与墙距选路进行试玩，检查哪些执行要求值得保留、哪些需要放宽。

## 可迁移的设计原则

- **压缩输入指令不等于消除全部执行门槛，须显式追踪门槛去向（原则：区分指令复杂度与节拍／空间判断）**：把反复出现的复合位移指令收拢进专用功能键可以降低搓招负担，但只要连段保留紧窗口衔接或墙距分支，操作压力只是从“输入复杂度”转移到了“节拍精度与位置判断”（本案依据：D 系集中了位移输入并实现三类位置路线，但长线关键 `jC` 仍有 1 帧窗口，见 [§1](./full.md#section-1)、[§3](./full.md#section-3)、[§5](./full.md#section-5)）。
- **为修复单条连段缩减招式前摇时，必须回查该招的常态攻防账（反模式：只为连段接上而孤立加速动作）**：缩短收尾技前摇虽能让特定路线从断连变成连续命中，但该招在立回、压制与被防结算中的风险收益会同步变化，必须放回同一套战斗结算里复验（本案依据：缩短 `2C` 前摇使版边两轮普通 D 后的扫倒接回同一连段，并同步核对整招攻防变化，见 [§4](./full.md#section-4)）。
